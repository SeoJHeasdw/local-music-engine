# 품질 검사와 청취 계약

## 기본 WAV 무결성 검사

현재 QC는 실제 WAV 파일을 PCM으로 디코딩해 다음을 기록한다.

- 파일 존재와 비어 있지 않음
- frame 수, sample rate, channel 수, sample width, 실제 길이
- peak, RMS, 절대 진폭 `0.0001` 이하 sample 비율
- 요청 길이와 실제 길이 차이
- SHA-256과 byte 수

헤더 frame 수와 실제 디코딩한 frame 수가 다르거나 마지막 frame이 잘리면 실패다. 8-bit WAV의
unsigned PCM을 보정하고 8/16/24/32-bit 정수 PCM을 검사한다. IEEE float WAV는 현재 Python
QC에서 지원하지 않으므로 무결성 통과로 기록하지 않는다.

50ms 창으로 모든 채널의 near-digital-silence가 0.5초 이상 이어지는 구간과 peak `0.999`
이상 구간을 찾는다. `silence_region` / `peak_region` finding은 실제 시간 범위를 갖는다.
유형당 긴 구간 최대 32개를 시간순으로 표시하고 전체 발견 수를 별도 기록한다. 앱의 **듣기**
버튼은 앞뒤 0.25초를 더해 선택·반복 재생한다. 시간 경계는 분석 창 단위이며 가사 정렬이나
음악적 결함의 판정이 아니다. 기존 후보의 과거 finding은 소급해서 덮어쓰지 않는다.

peak `0.999` 이상, near-digital-silence 비율 `0.2` 초과, 요청 길이 차이 `0.5초` 초과는
경고다. 의도된 쉼과 다이내믹을 결함으로 단정하지 않는다. 현재 ACE 출력의 -1 dB 정규화는
이미 생긴 왜곡을 고쳤다는 뜻이 아니다.

## 생성 버튼에 연결된 자동 품질 관리

새 생성의 기본 자동 관리에는 PCM 검사에 더해 가사 준비·밀도 확인, 보컬 활동 추정,
로컬 받아쓰기 비교, FFmpeg LUFS/LRA/true peak 측정, 제한된 재시도와 추천이 포함된다.
원문·실제 모델 입력·원본 후보·재생을 위해 정리한 새 파일을 각각 보존한다.

자동 재시도는 버전마다 **첫 생성 포함 총 4회**까지다. 전체에 가까운 무음, 지속적인
full-scale 샘플, 큰 길이 차이, 신뢰도 조건을 만족한 받아쓰기의 큰 가사 불일치가 근거다.
의도된 휴지·단발성 peak·조용한 도입은 재생성 근거로 쓰지 않는다. 받아쓰기나 검사 도구가
실패하거나 불확실하면 해당 검사를 `unknown`으로 남기며 그 실패를 이유로 재생성하지 않는다.

한국어 CER, 영어 WER와 후렴별 순서 일치는 **인식한 텍스트와 작성한 가사의 비교**다.
실제 발음 정확도나 음악적 완성도를 보증하지 않는다. 보컬 분리 결과도 활동·에너지의 참고
관측이며 음원을 분리하거나 보컬을 키워 결과 믹스를 다시 만드는 데 사용하지 않는다.

재생본 정리는 필요할 때 DC offset 제거, 최대 5ms의 파일 경계 fade, 선형 gain 감소만
적용한다. 측정 true peak도 gain 감소량에 반영한다. 원본은 남고 길이·sample rate·channel 수는
유지한다. 이미 생긴 clipping 복원, 고정 LUFS 정규화, 가사·멜로디 수정을 뜻하지 않는다.
세부 기준·환경·라이선스와 실제 검증은 [자동 품질 관리](AUTO-QUALITY.md)에 기록한다.

## 자동 검사가 보증하지 않는 것

- 한국어 발음의 정확성, ASR이 놓치거나 잘못 읽은 가사 누락·반복
- 보컬 자연스러움, 곡 구조, 음악적 선호
- repaint 시작/끝의 박자·음색·반주·음량 연결
- key/BPM/구조 추정 정확성
- Suno 또는 다른 서비스와의 품질 동등성

이 항목은 후보마다 `humanReview.status`를 `unreviewed`, `listened`, `approved`, `rejected`로
별도 기록한다. 자동 검사가 통과해도 기본값은 `unreviewed`다. 평점은 1–5 범위의 청취 메모일
뿐 자동 검사와 합산하지 않는다.

## repaint 검수

CLI와 앱의 repaint에도 기본 자동 검사·재생본 정리가 연결돼 있다. 생성된 수정 WAV 전체를
한 번 검사하며, 새 곡의 가사 준비·Outro 추가·길이 조정은 적용하지 않는다. 자동 재추론은
없다. 검사 실패는 `unknown`, 정리 실패는 검증된 수정 원본 유지로 처리한다. 편집 범위와
원곡 → 수정 원본 → 정리본의 계보, 기존 사람 선택을 보존한다.

선택 범위 앞뒤 문맥을 포함해 원본과 수정본을 번갈아 듣는다. 첫 실측에서 5–9초 repaint가
0–5초와 9–15초도 바꿨으므로, 선택 범위 밖 파형이 동일하다고 가정하지 않는다. 길이 보존과
파일 무결성은 자동 확인하지만 연결감은 사람이 확인한다. 마음에 들지 않으면 원본 후보의 선택을
유지한다.

2026-10-04 실제 repaint에서는 자동 상태 `attention`, 후렴의 ASR 일치 비율 0.70이
기록됐다. 재생성을 요청하지 않고 경고를 보존했다. 실제 가사 누락인지 ASR 오류인지는
아직 사람 청취 전이다. 세부 실측은 [자동 품질 관리 검증](AUTO-QUALITY.md#실제-검증)에 있다.

## 앱에서 확인한 모델 입력 문제 (2026-09-22 실측)

- **repaint 지시**: 기존 CLI는 `--instruction`에 자연어("Keep arrangement and improve Korean
  diction")를 넣었고, 이것이 ACE DiT 작업 템플릿을 덮어썼다. p0 수정본(`candidate_7aadaac…`)은
  이 방식으로 만들어졌으며 앱에서 "예전 방식" 경고를 표시한다. 지금은 캡션과 강도로 전한다.
  캡션 변경이 청취상 실제로 개선되는지는 아직 사람 청취 전이다.
- **ACE 0.6B LM 초안**: 한국어 설명("비 오는 밤… 잔잔한 발라드, 여자 목소리, 피아노")에 대해
  `upbeat, funky J-pop… winter holiday` 캡션과 로마자 가사(`[ko] nega iss-eo`)를 돌려줬다.
  같은 내용을 영어로 묻자 캡션은 맞았지만 가사는 여전히 로마자, BPM은 180이었다. 그래서 초안의
  한국어 이해와 한글 가사는 LLM 도우미에 맡기고, 엔진 초안은 영어 질의 + 캡션만 쓴다.
- **로컬 LLM(qwen3.6:27b, Ollama)**: 같은 설명으로 제목·태그·한글 가사를 24–40초에 썼다(모델
  로드 포함). 자유 문장 피드백 "가사가 웅얼거려서 잘 안 들리고, 목소리가 반주에 묻혀요"는
  `female vocals → prominent female vocals`, `+ clear vocal mix`로 해석했다. 발음 태그는
  넣지 않았으므로 수정안의 태그를 실행 전에 확인하는 단계를 없애지 않는다.

LLM 해석, 규칙 해석, 자동 검사, 사람 청취는 서로 다른 기록이다. 수정안이 실행됐다는 사실은
그 수정이 좋다는 뜻이 아니다.

## 로컬 모델 검사의 범위

보컬 분리는 MIT 가중치의 UMXHQ, 받아쓰기는 MLX Whisper large-v3-turbo를 사용한다.
별도 Python 3.12 환경과 이 저장소의 모델 캐시만 사용하며 기존 TTS 엔진과 의존성을 공유하지
않는다. 기대 가사를 ASR prompt로 주거나 forced alignment를 정확도 검사로 쓰지 않는다.
현재 받아쓰기는 원 믹스의 Whisper 내부 30초 창이며, 보컬 분리본의 활동 구간으로 ASR 창을
다시 나누는 방식은 아직 구현하지 않았다. 같은 ASR의 재실행을 독립 판독 여러 개로 세지 않는다.

음악적 일관성, 보컬 자연스러움, 악기·박자 연결은 사람이 청취한다. 자동 통과와 추천을 얻어도
`humanReview.status`는 `unreviewed`로 남는다.
