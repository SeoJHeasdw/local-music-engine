# Astra 개선 및 검증 기록

2026-09-22. 기존의 내 곡·초안·작업실·수정 도우미 구현 위에서 작업했다. 이전 에이전트의
커밋되지 않은 변경을 유지했으며 모델·음원·검증 프로젝트·실행 로그는 Git에 포함하지 않는다.

## 바뀐 동작

- 생성의 독점 잠금과 정본 저장 잠금을 분리했다. 생성 중 평가·메모를 메모리 대기열에 두지
  않고 즉시 저장하며, 다음 진행률 저장이 다른 프로세스의 변경을 덮지 않는다.
- 시작할 때 모든 seed의 입력을 고정한다. 현재 가사·스타일·길이를 바꿔도 진행 작업과
  이어 만들기는 최초 요청을 사용한다. 특정 batch를 재개하고 각 시도의 계보를 남긴다.
- SIGKILL 이후 실행 중인 작업과 중단된 기록을 구별한다. 완료 파일은 같은 재개 계보에서만
  크기·SHA-256 검증 후 재사용하며 다른 batch의 같은 seed를 가져오지 않는다.
- 오래된 버전을 고칠 때 그 버전의 가사·음악 설정을 사용한다. repaint는 실제 원본 길이를
  유지하며 이번 수정본의 가사 변경이 프로젝트 기본값에 섞이지 않는다.
- 외부 export가 원본·정본·기존 파일을 덮는 경로를 거부한다. 선택 되돌리기도 복원 파일을
  검증한다. 앱 시작 요청을 직렬화하고 종료 시 CLI 취소 기록을 기다린다.
- 잘린 WAV와 불완전한 frame을 거부하고 unsigned 8-bit 음량 측정을 수정했다. 무음·최대
  음량 경고에 시간 범위를 붙이고 앱에서 해당 부분을 바로 선택·반복 재생한다.
- 로컬 API 호출에서 환경 프록시와 리다이렉트를 차단했다. 앱 설정 저장의 임시 파일 충돌과
  동시 갱신도 방지한다. IPC 요청은 앱의 주 프레임에서만 받는다.

## 자동 회귀 검사

Python 3.12.12 환경에서 아래 명령을 실행했다.

```bash
uv sync --python 3.12.12 --group dev
uv run python -m compileall -q src tests
uv run pytest
npm run check:app
npm run test:app
npm run build:app
```

Python 62개, 앱 9개 테스트. Python 검사는 별도 프로세스에서 실제 SIGKILL, 동시 CLI
평가 저장, 생성 잠금 경합, 입력 변경 후 재개, 원격 ID 저장, 손상 파일 재생성, 이전 schema 1
복구, 덮어쓰기 거부, PCM 폭·채널·잘림·시간 구간, loopback HTTP 경계를 포함한다.
앱 검사는 CLI 결과·신규/재사용 구분·취소 종료, 오디오 Range, 동시 JSON 게시를 확인한다.
단위 테스트의 가짜 ACE client는 음악 추론의 검증으로 세지 않는다.

## 실제 ACE 추론

이 Mac의 기존 ACE-Step 1.5 native MLX 런타임을 별도로 `127.0.0.1:18002`에 실행했다.
사용한 모델은 `acestep-v15-turbo`, `acestep-5Hz-lm-0.6B`이다. 아래 시간은 이 환경의
실측 한 번이며 이전 코드 대비 속도 향상을 뜻하지 않는다. Ollama 동시 추론과 메모리 정량
측정은 이번에 수행하지 않았다.

| 실제 작업 | 결과 |
| --- | --- |
| 30초 곡, 2 seeds | 72.36초, 2개 모두 성공 |
| 생성 중 메모·다음 입력 저장 | 0.004초, 진행 중 요청에는 새 입력이 섞이지 않음 |
| 입력 변경 뒤 완료 batch 재개 | 0.01초, 원래 음원 2개 검증·재사용, 새 추론 0회 |
| 30초 원본의 8–13초 repaint | 26.45초, 부모 가사와 실제 원본 길이 유지 |
| 120초 곡, 4 seeds | 총 179.39초, 4개 모두 성공, 각 120.0초 / 23,040,078 bytes |
| 최종 코드의 재현 스크립트, 10초 × 2 seeds | 41.56초, 생성 중 저장 0.0106초 |
| 재현 스크립트의 검증 재사용 / repaint | 0.008초 / 6.54초 |
| export·재열기 | 모든 기록된 artifact의 크기·SHA-256 일치 |

실행 코드·리포트·음원은 `.runtime/validation-astra/`에 보관했다. `report.json`은 최초 실제
검사, `long-report.json`은 2분 4 seeds, `final-smoke/report.json`은 최종 재현 스크립트 결과다.

재현하려면 실제 서버를 켠 상태에서 존재하지 않는 새 출력 폴더를 지정한다.

```bash
uv run python scripts/smoke_real_engine.py \
  --output-dir .runtime/new-smoke --base-url http://127.0.0.1:18002 --duration 30
```

## Electron에서 확인한 동작

임시 앱 데이터 폴더를 사용해 실제 사용자 설정을 바꾸지 않았다. 빌드된 Electron을 열고
DevTools 프로토콜로 DOM 버튼을 클릭하고 화면을 캡처했다.

- 실제 생성 프로젝트의 사본에 실패 batch를 구성한 UI fixture를 열었다. **이어서 만들기**를
  누른 뒤에는 실제 ACE 서버에서 30초 음원이 생성됐다. 복구 배너가 사라지고 새 버전이 나타났다.
- 실제 생성 중 **메모 남기기**를 눌렀다. 화면에 저장 완료가 나타나기까지 154ms였으며
  완료 후 메모도 보존됐다. 모든 청취 상태는 `unreviewed`를 유지했다.
- 합성 PCM fixture의 2–3초 무음·50ms peak 구간을 검출했다. **듣기**를 누르면 앞뒤
  문맥을 포함한 1.75–3.25초 선택·반복 재생이 켜졌다. 이 검사는 음악 추론 검증과 별개다.
- renderer 예외가 없었으며 작업실·복구 배너·검사 구간 화면을 시각적으로 확인했다.

## 남는 한계

청취자는 아직 발음·가사 정확도·음악성·repaint 연결부를 평가하지 않았다. 자동 검사 성공이나
메모 저장을 청취 승인으로 바꾸지 않는다. 보컬 분리·한국어 ASR은 여전히 미구현이다.

ACE는 실행 중인 원격 task를 취소하는 API가 없다. 로컬 취소·강제 종료 뒤에도 이미 제출한
음원은 서버가 끝까지 계산할 수 있다. 재개는 원격 task에 재접속하지 않고 필요한 seed를
새로 제출한다. 앱이 강제 종료된 경우 앱이 띄운 ACE 서버 소유권을 다시 인수하는 기능도
아직 없다.
